# Ракета · Веб-система снабжения

Прогнозирование продаж, остатки и планирование закупок для магазинов Wildberries —
замена расчётов, которые сейчас живут в Google Sheets.

Реализация по ТЗ v0.5 от 09.11.2026. Расшифровка исходного ТЗ, включая блок-схемы
и макеты, — в [docs/00-tz-source.md](docs/00-tz-source.md). Рабочий список задач —
[BACKLOG.md](BACKLOG.md).

## Что уже работает

- **Единая недельная матрица** с тремя уровнями просмотра — магазины, категории,
  артикулы. Один экран, переключатель, без дерева строк.
- **Расчётное ядро:** исходный и адаптированный прогноз, реальный и адаптированный
  сток, DIFF, поставки, статусы OVER/SHORT. Правка прогноза сразу пересчитывает
  остатки, риски дефицита и закупку.
- **Закупочная потребность:** дата и объём заказа по исходному спросу с учётом
  остатков, партий в пути, lead time, MOQ, PCB, coverage и safety; результат в штуках,
  рублях, м³ и неделе прихода.
- **Загрузка WB:** адаптер с фикстурным и HTTP-клиентом, нормализация в недельные
  факты, идемпотентный upsert, журнал синхронизаций.
- **Правки прогноза:** поячеечные и массовые (×%, +шт, задать, сбросить, перенос
  спроса между неделями) — всё с журналом корректировок.
- **Справочные страницы:** базовый потенциал SKU с ориентиром по факту и сезонность
  категорий по неделям.

Что ещё не сделано и почему — в бэклоге, по эпикам и с открытыми вопросами к заказчику.

## Устройство

```
backend/   FastAPI + SQLAlchemy + PostgreSQL (в разработке — SQLite)
  app/calc/          чистое расчётное ядро: ни БД, ни HTTP
  app/services/      сборка матрицы, закупки, правок
  app/api/           HTTP-слой
  app/integrations/  Wildberries
frontend/  React + TypeScript + Vite
docs/      ТЗ, архитектура, спецификация формул, тест-кейсы
```

## Запуск

Нужны Python 3.11+ и Node 20+. PostgreSQL не обязателен: по умолчанию используется
SQLite в файле `backend/raketa.db`.

**Бэкенд**

```bash
cd backend
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements-dev.txt   # Linux/macOS: .venv/bin/python
.venv/Scripts/python -m app.seed --reset                      # демо-данные
.venv/Scripts/python -m uvicorn app.main:app --reload --port 8000
```

Документация API — http://127.0.0.1:8000/docs

**Фронтенд**

```bash
cd frontend
npm install
npm run dev
```

Интерфейс — http://localhost:5173, запросы к API идут через прокси Vite,
поэтому отдельный базовый URL настраивать не нужно.

**Проверки**

```bash
cd backend && .venv/Scripts/python -m pytest && .venv/Scripts/python -m ruff check .
```

```bash
cd frontend && npm run build
```

## Настройки

Все переменные необязательны, значения по умолчанию — в `backend/app/config.py`.

| Переменная | По умолчанию | Назначение |
|------------|--------------|------------|
| `DATABASE_URL` | `sqlite:///./raketa.db` | В проде — `postgresql+psycopg://user:pass@host:5432/raketa` |
| `WB_CLIENT` | `fixtures` | `fixtures` — локальные файлы, `http` — реальный API WB |
| `WB_TOKENS` | пусто | `store01=<токен>,store02=<токен>` — ключи кабинетов, в базе не хранятся |
| `CORS_ORIGINS` | `http://localhost:5173,...` | Разрешённые источники |

PostgreSQL для локальной разработки поднимается через `docker compose up -d db`.

## Состояние проекта

Это рабочая первая итерация, а не готовая к эксплуатации система. Главное, чего
не хватает для приёмки:

- Алгоритм DIFF и правила статусов OVER/SHORT реализованы как обоснованные
  допущения — их нужно сверить с действующими файлами заказчика (вопрос Q-1).
- HTTP-клиент WB написан, но не проверен на боевых ключах: кабинеты ещё не переданы
  (вопрос Q-3).
- Нет аутентификации и ролей, Alembic-миграций, массовых корректировок и графиков.

Полный перечень с приоритетами — в [BACKLOG.md](BACKLOG.md).
